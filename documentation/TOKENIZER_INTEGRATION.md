## 1. Overview & Verification

The IGRIS project mandates that **Candidate A** serves as the sole, authoritative production tokenizer for all inference and future training workloads. Experimental synthetic tokenizers or unverified substitutes are strictly prohibited.

### 1.1 Invariant Cryptographic Verification

Upon initialization, the inference engine loads the Candidate A artifact located at:
`c:\IGRIS\artifacts\tokenizer\candidate_a\tokenizer.json`

The SHA-256 hash is computed and validated against the invariant standard:

$$\text{Expected SHA-256} = \texttt{ac7e18b13973450b43bfff18609a833e4ef0e642b8dc5803e39ab1e81ba4c561}$$

```python
# Programmatic integrity assertion in igris/inference/engine.py
with open(candidate_a_path, "rb") as f:
    digest = hashlib.sha256(f.read()).hexdigest()

if digest != CANDIDATE_A_EXPECTED_SHA256:
    raise TokenizerIntegrityError(f"Tokenizer hash mismatch: {digest}")
```

If the hash does not match, the runtime fails loudly with a `TokenizerIntegrityError` and refuses to start.

## 2. Vocabulary Structure & Special Tokens

Candidate A uses a Byte-Level Byte-Pair Encoding (BPE) algorithm with a vocabulary size of **32,768** tokens.

### 2.1 The 12 Structural Special Tokens

Candidate A reserves exactly 12 structural special tokens configured at the head of the vocabulary in specification order:

| Token ID | Token String | Purpose |
| :---: | :--- | :--- |
| **0** | `<|pad|>` | Padding token for batch tensor alignment |
| **1** | `<|unk|>` | Unknown token fallback |
| **2** | `<|bos|>` | Beginning-of-sequence delimiter |
| **3** | `<|eos|>` | End-of-sequence delimiter |
| **4** | `<|system|>` | System turn prefix delimiter |
| **5** | `<|user|>` | User prompt turn delimiter |
| **6** | `<|assistant|>` | Model response turn delimiter |
| **7** | `<|turn_start|>` | Explicit conversational turn start |
| **8** | `<|turn_end|>` | Explicit conversational turn termination |
| **9** | `<|thought|>` | Internal reasoning trace delimiter |
| **10** | `<|speech|>` | Voice-First phoneme / audio transcript boundary |
| **11** | `<|action|>` | Tool execution and desktop command boundary |

### 2.2 Byte Fallback Mechanism

Tokens 12 through 267 represent the 256 individual byte values (`0x00` through `0xFF`). This guarantees:
- **Zero Out-of-Vocabulary (OOV) Errors**: Any arbitrary UTF-8 sequence can be represented.
- **Robust Tamil Character Handling**: Complex Tamil consonants, vowel signs, and conjuncts (e.g. `க்ஷ`, `ஸ்ரீ`) are encoded either as optimized multi-character BPE merges or broken into byte sequences without loss.
- **Phonetic Tanglish Robustness**: Mixed English/Tamil colloquial text (e.g. `enna bro`, `romba nalla irukku`) is tokenized smoothly.

## 4. Frontend & Backend Integration

Prior to this implementation, the frontend estimated token counts using heuristic character multipliers. With the local inference runtime active:
1. **Chat Completions**: The backend runs `tokenizer.encode(prompt)` and `tokenizer.decode(generated_ids)`.
2. **Usage Telemetry**: The server returns exact integers for:
   - `prompt_tokens`: Actual tokens consumed by the context prompt + Candidate A structural delimiters.
   - `completion_tokens`: Actual tokens generated by the model.
   - `total_tokens`: $P + C$.
3. **SSE Streaming**: The final SSE chunk sends the exact `usage` dictionary calculated directly from Candidate A.

Candidate A is now the operational foundation of the IGRIS inference pipeline.
